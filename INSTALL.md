# Установка и эксплуатация 4VRS Add-ons

## Требования

Экспериментальная надстройка для уже подготовленного Aqara M2. Проверено только на модели и прошивке из README. Нужны рабочая root-консоль UART и собственная проверенная резервная копия. Получение root и восстановление NAND не автоматизируются этим проектом.

Приложение не меняет загрузчик, ядро, Zigbee-прошивку, заводскую идентичность или штатный MQTT. Все постоянные файлы приложения находятся в `/data/aqara-panel`. Для автозапуска отдельно устанавливается минимальный хук в rootfs; дальнейшие обновления приложения rootfs не затрагивают.

Для установки из комплекта используйте [инструкцию установщика](installer/README.md). Она описывает сборку архива без личных данных, проверку совместимости, установку с резервной копией предыдущей версии и отдельную подготовку rootfs-хука. Ниже остаётся ручной способ установки и описание эксплуатации.

## 1. Сборка

На компьютере установите Go 1.27.1 или совместимую версию. Используется чистый Go, без CGO.

Linux/macOS:

```sh
cd webpanel
go test ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=mipsle GOMIPS=softfloat go build -trimpath -ldflags="-s -w" -o panel-mipsle .
```

PowerShell:

```powershell
cd webpanel
go test ./...
go vet ./...
$env:CGO_ENABLED='0'
$env:GOOS='linux'
$env:GOARCH='mipsle'
$env:GOMIPS='softfloat'
go build -trimpath -ldflags '-s -w' -o panel-mipsle .
Remove-Item Env:GOOS,Env:GOARCH,Env:GOMIPS,Env:CGO_ENABLED
```

## 2. Индивидуальные пароль и сертификат

На компьютере, в каталоге webpanel:

```sh
go run . -data ../secrets/panel-identity -init <IP-хаба>
```

Флаг `-init` создаёт:

- `panel-password.txt`: начальный пароль панели, оставьте на своём компьютере;
- `auth.sha256`: проверочное значение пароля; после смены через UI здесь хранится PBKDF2-HMAC-SHA256 с индивидуальной солью и 100000 итераций;
- `server.crt` и `server.key`: индивидуальный самоподписанный сертификат и закрытый ключ.

Генерация откажется перезаписывать существующую идентичность. Не публикуйте каталог secrets. Резервная копия identity позволяет восстановить доступ к панели.

## 3. Доставка на M2

Через root UART создайте `/data/aqara-panel` с правами 0700. Доставьте туда собранный файл как `panel`, а также `auth.sha256`, `server.crt`, `server.key`.

Предпочитайте защищённый доступ либо передачу приватных файлов непосредственно по UART с отключённым эхом. Не помещайте пароль или ключ в историю команд. Большой бинарный файл можно передавать по доверенной LAN через временный nc/wget, но **до запуска сравните SHA256 на компьютере и хабе**. Проверяйте и размер: в наших опытах старый BusyBox nc при слишком раннем закрытии соединения мог не дописать хвост файла.

Права:

```sh
chmod 700 /data/aqara-panel
chmod 700 /data/aqara-panel/panel
chmod 600 /data/aqara-panel/auth.sha256 /data/aqara-panel/server.crt /data/aqara-panel/server.key
```

Старт из UART:

```sh
GOMEMLIMIT=12MiB GOGC=50 /data/aqara-panel/panel > /var/tmp/aqara-panel.log 2>&1 &
echo $! > /data/aqara-panel/panel.pid
```

Откройте `http://<IP-хаба>` (порт 80). Логин — `admin`, пароль — из созданного `panel-password.txt`. Для собственного HTTPS запускайте панель с флагами -https -listen :443 и проверьте индивидуальный сертификат. Для HTTPS на обратном прокси передавайте исходный Host на HTTP backend хаба; панель сохраняет собственную Basic-авторизацию и проверку Origin. Проверка TLS внешнего MQTT от режима веб-панели не зависит.

## 4. Веб-панель

### MQTT

Введите сервер, порт, логин и пароль. Пустое поле пароля при сохранении сохраняет прежний пароль; для удаления есть отдельный переключатель. TLS с собственным CA требует PEM-сертификат. В урезанной прошивке может не быть системного хранилища корневых сертификатов — в таком случае укажите CA явно.

Проверьте подключение, включите передачу и сохраните настройки. Для штатного подключения используется Client ID из формы; тест использует отдельный случайный суффикс, чтобы не вытеснять основной клиент.

Мост публикует сырой JSON в `<prefix>/zigbee/send`. Дополнительно включите «Создавать устройства в Home Assistant», если HA подключён к этому брокеру. Используется стандартный префикс Discovery homeassistant; на брокере нужны соответствующие права публикации. До первого события показания могут оставаться неизвестными. При отключённом мосте его подключения к обоим брокерам закрываются.

### Устройства

Откройте /devices по тому же адресу. Для открытия сопряжения и настройки P1 внешний MQTT не нужен. Обратные команды через внешний брокер не принимаются. Для автоматического добавления сущностей в HA нужен включённый MQTT Discovery.

Аппаратные изменения P1 могут применяться с задержкой: сначала статус «Принято», затем подтверждение датчика. Если подтверждение не пришло, кратко нажмите кнопку на корпусе и повторите. Долгое удержание используется только для намеренного сопряжения.

### Пароль панели

Введите текущий пароль, новый и повтор. Минимум 12 символов. Новый пароль сохраняется как PBKDF2-хеш и начинает действовать сразу. Браузер может запросить повторный вход через стандартное окно HTTP Basic. Системный пароль root не меняется.

### Копия root/UART-пароля

Необязательный файл `/data/aqara-panel/root-password.txt` с правами 0600 содержит **только сохранённую копию**. Его можно заполнить через «Обновить сохранённую копию root-пароля».

«Показать пароль root» раскрывает его только по явному запросу вошедшего администратора. Значение скрывается через 20 секунд или при уходе со страницы. Обновление копии никогда не запускает passwd/chpasswd. Панель не проверяет, совпадает ли копия с настоящим системным паролем.

Пользователь веб-панели получает возможность прочитать root-пароль, если вы его там сохранили. Используйте индивидуальный пароль панели и доверенную LAN.

### Сеть Ethernet

Показываются MAC eth0, текущие IPv4, маска, шлюз и DNS. Можно выбрать DHCP или статические IPv4-параметры. Управление Wi-Fi и изменение MAC не реализованы.

Изменение сети запускается с отдельным процессом отката. **В течение 90 секунд откройте панель по новому адресу и подтвердите доступ.** Без подтверждения должны восстановиться исходные IP/маршрут/DNS и режим DHCP. При смене IP браузер может предупредить о несовпадении адреса с сертификатом; сертификат автоматически не перевыпускается.

При возвращении в DHCP адреса и шлюз определяет DHCP-сервер; он может выдать новые значения.

Параметры сети действуют до перезагрузки. Автоматическое применение подтверждённой конфигурации при загрузке пока не реализовано. Подтверждённая запись сохраняется для диагностики, но не является обещанием постоянной конфигурации.

На этапе экспериментов сохраняйте рабочий UART: резервный механизм не заменяет аппаратный доступ при отказе питания или всей системы.

## Перезапуск и автозапуск

Пароль панели и настройки MQTT находятся в `/data` и сохраняются после перезагрузки. На тестовом HM2-G01 проверен автозапуск через минимальную правку `rcS` собственного rootfs. Штатная прошивка не вызывает `/data/scripts/post_init.sh`; копирование одного скрипта не включает автозапуск.

Установленный хук запускает `/bin/sh /data/aqara-panel/autostart.sh` в фоне после штатных служб. Скрипт из `webpanel/autostart.sh` предотвращает дублирование, запускает панель на HTTP-порту 80 и перезапускает её после завершения с задержкой 5–60 секунд. MQTT-мост является частью процесса панели. PID супервизора: `/var/run/aqara-panel-supervisor/pid`, PID панели: `/var/run/aqara-panel.pid`. Последний код завершения: `/var/run/aqara-panel-supervisor.status`. Журналы процесса в этом режиме не накапливаются.

Файл `/data/aqara-panel/autostart.disabled` запрещает последующий автоматический запуск. Для немедленной остановки сначала создайте этот файл, затем проверьте командную строку PID супервизора и отправьте ему SIGTERM: он остановит и свою панель. Для повторного включения удалите маркер и запустите скрипт в фоне либо перезагрузите хаб. Не останавливайте штатные mosquitto, zigbee_agent и ha_master.

Изменение rootfs проверено только на конкретном хабе. Образ не распространяется как универсальная прошивка: установка требует проверки модели, банков, контрольных сумм и доступного UART-восстановления.

## Откат надстройки

1. Дождитесь окончания всех сетевых транзакций, восстановите нужный DHCP/static режим.
2. Если настроен автозапуск, создайте `autostart.disabled` и остановите проверенный PID супервизора. При ручном запуске остановите только PID панели.
3. Уберите её файлы из /data/aqara-panel или оставьте для следующего запуска.
4. Штатный MQTT и HomeKit продолжают обслуживаться штатными процессами.

Удаление надстройки не откатывает ранее выполненные отдельно изменения root-пароля/UART. Установленный хук rootfs ничего не запускает при отсутствии скрипта либо наличии `autostart.disabled`. Возврат заводского rootfs является отдельной операцией восстановления.

## Проверки

`go test ./...` проверяет авторизацию, отсутствие выдачи секретов в обычном API, защиту запросов от CSRF, атомарное сохранение настроек, PBKDF2-пароль после повторного чтения, обновление только копии root-пароля, валидацию сети, MQTT CONNECT и передачу события между двумя тестовыми MQTT-брокерами.

Результаты проверки на реальном M2 и текущие ограничения перечислены в README. Не считайте тест на одной ревизии гарантией совместимости со всеми M2.

## Обновление через браузер (начиная с 0.4.0)

Откройте «Обновление надстройки» (`/maintenance`). Выберите архив приложения `4vrs-m2-<версия>.tar` и вставьте 64 символа SHA256 из соседнего `.tar.sha256`. Нажмите «Загрузить и проверить», проверьте показанную версию, затем «Установить проверенный пакет». Страница повторно подключится после перезапуска.

Поддерживается штатный для надстройки HTTP-порт 80. Первую версию с этой функцией устанавливают через UART. Во время обновления не отключайте питание. Нужен свободный объём не меньше размера архива плюс 2 МиБ; архив распаковывается потоком, его вторая копия на хабе не хранится.

Проверяются SHA256 всего архива и каждого файла, модель и платформа манифеста, архитектура ELF, допустимые имена файлов и отсутствие ссылок/обхода каталогов. SHA256 не является подписью издателя: выбирайте пакет из доверенного источника. Произвольные установочные скрипты из архива не выполняются.

Сохраняется одна предыдущая версия в `web-previous`. При неудачном запуске новая версия заменяется старой. Восстановление прерванной транзакции выполняется супервизором при следующем запуске. Неисправность накопителя или самой штатной загрузки может потребовать UART; полного отсутствия риска обновление не гарантирует.

MQTT-настройки, авторизация и база Zigbee не заменяются; rootfs, ядро и загрузчик не прошиваются. После успешного обновления проверьте реальные события в HA: проверка запуска веб-панели не заменяет такую проверку. Версии до 0.4.0 не являются пакетами для этого веб-обновлятора.
